# Plan: the stack and the end-to-end test

Tracking issue: #8. Milestone: `stack e2e`. Pull request: #7.

CONTRACT.md says this repository holds a Docker Compose file that runs all four projects together and an end-to-end test of the path in its diagram. This plan builds both, so a newcomer can try the whole stack with one command and gaps between the projects show up early.

## Decisions

- **Images.** None of the four publishes an image yet, and only transponder ships binaries. A Dockerfile in this repository builds any of them from GitHub at a tag or branch. The released tags are the defaults: airlock v0.1.0, rosetta v0.1.0, transponder v0.3.0, logbook v0.1.1.
- **No provider keys.** transponder answers every model and embedding with its `echo` provider.
- **Identity.** One shared key is not possible today: airlock takes only `alk_` keys, logbook only `lbk_` keys, transponder keys from its store, and airlock and rosetta have no OIDC yet. Each hop uses a public demo service key. One identity across all four waits on raven-clown/airlock#10 and raven-clown/rosetta#45.
- **Seeing each hop.** The test sends its own `traceparent` and `X-Request-ID`, then finds them in transponder's usage records, Jaeger, airlock's audit records and logbook's request logs.
- **Gaps.** A step a project can't do yet is skipped with the link to that project's issue, never worked around in this repository.

## Tasks

1. **Compose file and build Dockerfile** (#9, size M). `deploy/compose/compose.yaml` and `deploy/compose/Dockerfile`. Every service healthy on `/readyz` with `docker compose up --build --wait`, ports on 127.0.0.1, `*_REF` picks another tag or branch.
2. **Project configs and seed steps** (#10, size M). One YAML file per project and `logbook-seed.sh`, wired as the contract draws them: rosetta to transponder and airlock, airlock to logbook. `transponder-seed` runs transponder's `sim seed`, and `logbook-seed.sh` makes the key airlock calls logbook with.
3. **End-to-end test** (#11, size L). `e2e/` as its own Go module, built with `-tags e2e`. It walks the diagram and checks usage, audit, the stored memory, and the forwarded headers on each hop.
4. **CI workflow** (#13, size S). `.github/workflows/e2e.yml` runs the stack and the test on pull requests, on main and every night, and the nightly run also builds every project from main.
5. **Docs** (#12, size S). A "Run the whole stack" section in the README, and `AGENTS.md` updated for the layout and commands.

## Gaps found

| Issue | What it blocks |
|---|---|
| raven-clown/airlock#59 | airlock sends `${LOGBOOK_KEY}` in `auth.headers` unresolved, so the airlock to logbook steps are skipped |
| raven-clown/transponder#205 | `echo` never answers with a tool call, so the agent never calls a logbook tool. That step also waits on raven-clown/airlock#59 |
| raven-clown/logbook#43 | logbook has no embeddings endpoint, so it never calls transponder |
| raven-clown/rosetta#45, raven-clown/airlock#10 | the caller's identity doesn't travel the whole path |

A skip in `e2e/diagram_test.go` names every issue it waits on. Once all of them are closed, replace the skip with the check it stands for, in the same change that bumps the project's tag in `compose.yaml`. Deleting the `t.Skip` line alone would leave a subtest that passes while checking nothing.
